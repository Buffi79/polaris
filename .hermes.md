## Worum es geht (Rangfolge)

1. **Das Projekt baut zuverlässig.** Aktuell baut es nur umgebungsabhängig.
2. **Ein Docker-Image erstellen**, das **Frontend (+`polaris-web/`) und Backend (Rust)** zusammen als einen Dienst ausliefert (Port 5050).
3. **Erst wenn es im Docker läuft:** die Sonos-Integration fertigstellen.

## Projektstruktur

- Backend (Rust): Projektstamm — `src/`, `Cargo.toml`. Server: axum, Streams Audio, Index, Playlists, Auth. Sonos-Erweiterung unter `src/sonos/`, `src/server/axum/sonos_api.rs`, `src/server/dto/sonos*`, `src/app/config/sonos.rs`.
- Frontend (Vue 3 + Vite + Tailwind): eigener Git-Repo-Unterordner **`polaris-web/`** (eigene `.git`-Wurzel). Build-Output wird vom Backend über `web_dir` serviert.

## Nächster Schritt (Hauptziel): Docker-Build verifizieren

Voraussetzungen im Linux: `docker` + `docker compose` (v2). Dann im Projektstamm:

```bash
docker compose up -d --build
# bzw. einzeln:
docker build -t polaris:latest .
docker run -d --name polaris -p 5050:5050 \
  -v polaris-data:/var/lib/polaris \
  -v /pfad/musik:/music:ro polaris:latest
```

Danach prüfen: `http://localhost:5050` zeigt den Initial-Setup-Flow.

**Wichtig beim Dockerfile:** Der Rust-Build-Stage braucht `build-essential pkg-config libssl-dev` (bereits drin). `npm install` statt `npm ci` verwenden (Lockfile kann nach dem Pin momentan abweichen). Container muss mit `--foreground` laufen (siehe entrypoint), sonst daemonisiert Polaris und PID 1 endet.

Falls `docker build` Fehler wirft: Fehlermeldung analysieren und beheben. Auch möglich, Backend ohne Docker zu verifizieren:
```bash
cargo build --release   # im Stamm; rustup stable + build-essential nötig
(cd polaris-web && npm install && npm run build)
```

## Danach: Sonos-Integration fertigstellen

- Backend-Router: `src/server/axum/sonos_api.rs` (authentifizierte Endpunkte unter `api/sonos/*`). Enthält noch viel auskommentiertes "DEBUG:"-Logging.
- Service: `src/sonos/mod.rs` (`SonosService`, spricht node-sonos-http-api an; Play über `x-file-cifs://`-URI via `setavtransporturi` + `play`; Mount-Virtual-Pfad → Ordner-Name-Mapping).
- Config: `src/app/config/sonos.rs` (`api_url`, `mp3_server`; Defaults `http://192.168.0.5:5005` / `192.168.0.6/mp3` — an Zielumgebung anzupassen, nicht hartcodieren).
- Frontend: `polaris-web/src/stores/sonos.ts`, `services/audioRoutingService.ts`, `components/playback/AudioOutputButton.vue`, `settings/Sonos.vue`.
- Unaufgeräumtes ignorieren: `*.rs.backup`, `*.backup2`, `readme.txt`, `temp_audio_routing_fix.txt` — das sind Notizen/Altsichern, kein aktiver Code.
